# 多轮规划代理在真实工具环境中的稳健性研究问题陈述

## 1. 研究问题核心

本研究旨在系统性地评估和提升多轮规划代理（Multi-turn Planning Agent）在面对真实、动态且不可预测的工具环境时所表现出的稳健性（Robustness）。核心关注点在于：当代理依赖的外部工具或环境状态发生预期外的变化（如工具失效、API变更、输入数据漂移、环境反馈延迟或错误）时，代理能否维持其任务目标的达成能力、规划逻辑的一致性以及行为的安全性。

## 2. 评估维度与可观测指标

为量化和分析代理的稳健性，定义以下核心评估维度及对应的可观测指标：

### 维度一：任务完成稳健性 (Task Completion Robustness)
*   **定义**：代理在扰动环境下最终成功完成目标任务的能力。
*   **可观测指标**：
    *   **成功率 (Success Rate)**: 在包含预设扰动的测试集上，代理成功完成任务的比例。
    *   **任务完成时间偏差 (Task Completion Time Deviation)**: 相对于无扰动基线，完成任务所需额外步骤或时间的增加量。
    *   **目标偏移度 (Goal Drift)**: 代理最终行为结果与原始任务目标之间的语义或功能差距。

### 维度二：规划适应性 (Planning Adaptability)
*   **定义**：代理检测环境异常并动态调整其多轮规划策略的能力。
*   **可观测指标**：
    *   **异常检测准确率 (Anomaly Detection Accuracy)**: 代理正确识别工具/环境异常的比率。
    *   **恢复策略有效性 (Recovery Strategy Effectiveness)**: 在检测到异常后，代理采取的修正措施成功使任务回到正轨的比例。
    *   **规划重规划频率 (Re-planning Frequency)**: 单位任务内因环境变化而触发完整或部分重新规划的次数。

### 维度三：行为安全性与一致性 (Behavioral Safety & Consistency)
*   **定义**：代理在应对扰动时，其行为是否符合预设的安全边界，并保持内部逻辑的一致性。
*   **可观测指标**：
    *   **安全违规次数 (Safety Violation Count)**: 代理执行了违反预设安全规则（如越权操作、危险指令）的次数。
    *   **逻辑矛盾率 (Logical Inconsistency Rate)**: 代理在连续对话或行动中出现自相矛盾陈述或决策的比例。
    *   **无效/冗余操作比例 (Ratio of Invalid/Redundant Actions)**: 因未能正确理解环境状态而产生的无效或重复操作占总操作数的比例。

## 3. 关键变量 (Key Variables)

*   **自变量 (Independent Variables)**:
    *   **扰动类型 (Perturbation Type)**: 工具失效（完全/部分）、API响应格式变更、输入数据噪声/缺失、环境状态延迟、虚假反馈等。
    *   **扰动强度 (Perturbation Severity)**: 扰动发生的频率、持续时间及对工具功能的影响程度。
    *   **代理架构 (Agent Architecture)**: 不同的规划算法（如ReAct, Plan-and-Execute, LLM-based planners）、记忆机制、反思模块等。
*   **因变量 (Dependent Variables)**:
    *   上述各评估维度下的所有可观测指标。
*   **控制变量 (Control Variables)**:
    *   基础任务难度、使用的语言模型（LLM）版本、工具环境的基线状态、评估数据集。

## 4. 假设条件 (Assumptions)

1.  **工具接口稳定性假设**：在无扰动情况下，工具环境提供稳定、符合文档描述的接口和响应。
2.  **代理目标明确性假设**：代理在任务开始时被赋予清晰、无歧义的最终目标。
3.  **观测完备性假设**：代理能够通过其工具调用和环境反馈获得足够的信息来推断当前状态（尽管该信息可能被扰动污染）。
4.  **LLM基础能力假设**：底层语言模型具备基本的推理、规划和文本理解能力，稳健性问题主要源于规划层与动态环境的交互。

## 5. 边界约束 (Boundary Constraints)

1.  **环境范围**：研究聚焦于可通过API或命令行工具进行交互的数字环境（如Web应用、数据库、代码解释器），不包括物理机器人环境。
2.  **扰动范围**：考虑的扰动是工具层面的非恶意故障或变更，不包括对抗性攻击（Adversarial Attacks）或环境本身的恶意欺骗。
3.  **时间尺度**：评估的是单次任务会话（Session）内的稳健性，而非长期运行中的概念漂移（Concept Drift）适应能力。
4.  **资源限制**：评估过程需考虑计算资源（如最大思考步数、工具调用次数上限）的现实约束。
